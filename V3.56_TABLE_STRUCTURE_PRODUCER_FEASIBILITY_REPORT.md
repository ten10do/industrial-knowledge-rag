Toolchain findings recorded during the audit (facts):

- pypdf 6.14.2 visitor callbacks are unreliable for same-line horizontal advances:
  memoized positions reset to (0,0) with phantom leading spaces. The experimental reader
  therefore consumes pypdf's PARSED CONTENT OPERATIONS instead — still real parser output,
  strictly more primitive than visitor text.
- "Rotated text discovered. Output will be incomplete." warnings appear on some real
  pages: rotated pages degrade any text-based reconstruction (out of scope for fixtures).
- The production path (`PyPDFLoader -> PageText(page,text) -> chunker`) discards ALL
  geometry today; nothing in the frozen runtime reads coordinates.

## 4. Experimental Producer (protocol 12.2/12.3)

`backend/retrieval/table_structure_producer_v356.py`
(sha256 `4dc23edafb34d4e4a22fb1ff354a719b149d93f2901f82c8db88b6080e8d54ad`)

- Deterministic, versioned (`table-structure-producer-v356-feasibility`), hashable
  (`ReconstructionReport.result_digest()`), no LLM, no OCR, no new dependencies.
- Input: `PageSignal` lists produced by `extract_page_signals()` from pypdf page objects;
  every field is really obtainable (text, Tm x/y, Tf size).
- Pipeline: coordinate clustering -> dense-core run detection -> size-guarded dilation
  (span-interior rows rejoin) -> header-band split by type-size contrast -> caption
  capture beyond 1.45 pitches -> leaf/ancestor header paths (nearest-left spanning rule)
  -> vertical-merge detection from empty-cell topology.
- Binding routes (structure topology decides the relation):
  - Route A `COLUMN_BOUND`: model row labels x parameter leaf headers; cross-row binding
    emitted ONLY when a detected vertical merge covers it (V3.54 coverage rescue).
  - Route B `DIRECT_ROW`/`SECTION_INHERITED`: parameter as row label; section scope must
    match the captured caption slug.
  - Route C `HEADER_INHERITED`: parameter only in the header lineage (unit/parent cases);
    suppressed under COLUMN_BOUND topology to prevent dual-relation duplicates.
  - Route D `CROSS_REFERENCE`: reference-pattern cells ("See ...", "Refer to ...").
- Precision-first declines: `BINDING_NOT_FOUND`, `AMBIGUOUS_BINDING` (>1 distinct
  location). No ANSWER/ABSTAIN decision, no query reasoning, no evidence sufficiency,
  no identity decision, no generation. Forbidden conclusion fields rejected by the frozen
  V3.51 validator remain rejected for producer output (tested).
- NOT wired: `backend/retrieval/__init__.py` unchanged (tested).

## 5. Benchmark (protocol 12.4/12.5)

Private, gitignored (`backend/evaluation/benchmark_private/v356_producer_feasibility/`):

- Deterministic raw-PDF generator (Helvetica base font, absolute Tm, FlateDecode);
  byte-stable SHA256 per fixture; ground truth declared by construction.
- 72 fixtures = 12 categories x 6 variants (>= 64 preferred, 48 minimum): simple tables,
  multi-level headers, colspan headers (parent-level parameters), merged model columns
  (rowspan + coverage rescue), deep row-spans (depth up to 9, double merges),
  qualifier/action cells, min/default/max matrices, model matrices, unit inheritance,
  configuration matrices, reference/note cells, multipage replication (2-page copies).
- Claims: 144 VALID / 138 INVALID / 8 AMBIGUOUS = 290 bindings. INVALID kinds:
  wrong value, cross-model (adjacent-span traps), cross-column, cross-parameter,
  wrong relation, wrong target. AMBIGUOUS: duplicated anchor labels or duplicated
  leaf names with shared value strings.
- Condition A (ground-truth ceiling): perfect-structure satisfiability search through
  the same frozen validators. Ceiling: valid support 144/144; invalid rejection 119/138
  (86.23%). The 19 non-rejectable invalids are WRONG_RELATION claims whose swapped
  relation is genuinely structure-compatible; the ceiling is a property of the claim
  set, not of the producer (the producer rejects 100% via relation mismatch).
- Condition C (flat-text control): naive line-adjacency binder over plain extracted
  text (the forbidden FLAT_TEXT_OWNERSHIP_INFERENCE style). It accepts only 38.89% of
  valid bindings while accepting 54/146 = 36.99% of invalid ones — it cannot distinguish
  ownership. Never treated as authoritative anywhere in the pipeline.

## 8. Known limitations (honesty items)

1. Fixtures are synthetic-but-realistic rendered PDFs; they flow through the genuine
   pypdf path, but real-manual layouts (wrapped cells, multi-line headers, rotated pages)
   are harder. This gap is exactly V3.57's DEV-benchmark job on official manuals.
2. Horizontal (colspan) DATA cells are not reconstructed; only vertical merges feed the
   V3.54 coverage contract. Header-level colspans are handled by the nearest-left
   lineage rule.
3. Fragment end-x is not computed (start-position clustering only); very narrow column
   pitch (< ~2x tolerance) could mis-cluster on real documents.
4. Rotated pages degrade extraction (pypdf warning observed on real manuals).
5. The A-ceiling rejects only 86.23% of invalids because WRONG_RELATION claims whose
   swap is structure-compatible are satisfiable by construction; the producer's stricter
   relation derivation rejects them all.
