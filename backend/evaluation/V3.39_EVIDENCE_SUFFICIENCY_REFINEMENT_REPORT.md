# V3.39 Evidence Sufficiency Refinement Report

## Decision

**PARTIAL**

The final `evidence-v339-sufficiency-candidate` improved answerable recall but
did not satisfy the safety or false-refusal acceptance gates. It is an
experimental artifact only and must not be promoted to production or advanced
to a sealed gate.

### Benchmark limitation found after the baseline

The design annotation marked every query as identity-compatible, but runtime
identity extraction returned 53 COMPATIBLE, 23 INCOMPATIBLE, and 4 UNKNOWN.
Ten of the baseline's 14 false refusals were stopped by the unchanged identity
boundary. This means the DEV set did not fully realize the intended
"identity already correct" precondition. The frozen benchmark was not edited
after observing this result. Consequently, V3.39 can measure the composed
boundary, but it overstates the portion of FR that the authorized Evidence-only
change can recover.

## 2. Failure taxonomy

The requested taxonomy is:

- `SAFE_RELAX_CANDIDATE`: sufficient local evidence is present and the identity
  boundary permits delegation;
- `UNSAFE_RELAX`: answering would bypass an identity/scope/safety boundary, or
  no relaxation is needed;
- `MISSING_EVIDENCE`: the necessary evidence was not selected;
- `SCOPE_AMBIGUITY`: more context is required to bind scope;
- `PARSER_LIMIT`: the required structure was not recovered.

The initial frozen runner used gold-chunk selection before the runtime identity
result and reported 6 safe, 66 unsafe, and 8 missing. A post-run identity-aware
audit, without changing any query or decision, corrected the attribution to:

| Class | Count |
|---|---:|
| SAFE_RELAX_CANDIDATE | 3 |
| UNSAFE_RELAX | 76 |
| MISSING_EVIDENCE | 1 |
| SCOPE_AMBIGUITY | 0 |
| PARSER_LIMIT | 0 |

For the 14 baseline false refusals specifically, the runtime attribution was 10
identity-boundary refusals, 3 safe local relax candidates, and 1 missing/local
relation failure. The public taxonomy helper now explicitly prevents an
INCOMPATIBLE identity result from being labeled safe.

## 3. Candidate design

The additive implementation is
`backend/retrieval/evidence_sufficiency_v339.py`. It does not replace or edit
the existing Evidence contract. Its execution order is:

1. unchanged V3.36 identity boundary;
2. unchanged `evidence_mixed.py` formal path;
3. only for a soft verification abstention, evaluate a bounded compatible
   evidence relation;
4. return ANSWER only when a single local candidate block covers the identity,
   values, units, and salient proposition terms.

The candidate preserves an identity INCOMPATIBLE result, does not join values
across documents or candidates, does not use broad model aliases as parameter
ownership, and refuses procedure, negated/exclusive, explicit contradiction,
and adverse-scope relaxation. It does not modify retrieval, parser, NLI,
support, open sufficiency, or `identity_reasoning.py`.

## 5. Candidate experiments

No more than three candidate experiments were run.

| Experiment | Hypothesis/change | Accuracy | FR | FA | Unsafe relax | Decision |
|---|---|---:|---:|---:|---:|---|
| E1 | Same-local-block lexical/value relation | 60.00% | 32.50% | 47.50% | 1 | PARTIAL |
| E2 | Support attached units such as `0.3ms`; reject explicit contradiction | 62.50% | 25.00% | 50.00% | 2 | PARTIAL |
| E3 | Require exact model ownership; reject adverse scope and broad aliases | 62.50% | 27.50% | 47.50% | 1 | PARTIAL |

E3 recovered three true ANSWER cases: one parameter-block association, one
table-value association, and one same-product installation value. It also
incorrectly relaxed one same-family power-supply permissibility case. The
evidence described operation with adverse conditions rather than an
unqualified supported permission; local lexical/value co-occurrence was still
not sufficient to determine the proposition's polarity and safety scope.

## 6. Safety analysis

| Acceptance check | Result |
|---|---|
| FR reduction >= 50% | FAIL (21.43%) |
| FA increase <= 5 pp | PASS (+2.50 pp) |
| Unsafe relax = 0 | FAIL (1) |
| Identity hard-negative FA unchanged | FAIL (8 -> 9) |
| Runtime integrity | PASS |

The central result is negative: a lightweight local relation layer can recover
some compact table and parameter facts, but lexical locality cannot safely
resolve permissibility, contradiction, and adverse conditional scope. Further
blanket relaxation would directly violate the V3.39 objective.

## 7. Runtime integrity and tests

The evaluation recorded identical before/after SHA-256 values for retrieval,
ingestion/parser, identity reasoning, base Evidence, Evidence contract,
mixed Evidence, open sufficiency, support, and local NLI files. Baseline
reproduction had zero mismatches.

- Backend: `654 passed, 2 skipped`.
- V3.39 focused tests: `15 passed` after the final taxonomy audit.
- Frontend: Vite production build passed (`1,829 modules transformed`).
- The direct PowerShell `npm` shim was blocked by local execution policy;
  invoking the same build through `npm.cmd` passed.
