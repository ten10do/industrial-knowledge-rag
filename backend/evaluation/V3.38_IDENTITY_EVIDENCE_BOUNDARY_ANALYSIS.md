# V3.38 Identity + Evidence Sufficiency Boundary Analysis

## Decision recommendation

**ENTER_EVIDENCE_SUFFICIENCY_REFINEMENT**

The new DEV-FR diagnosis attributes **14 of 20 false refusals (70.00%)** to
`EVIDENCE_TOO_STRICT`. This is the only pre-registered failure class above the
strict `>30%` routing threshold. `IDENTITY_ERROR` accounts for 5.00%,
`RETRIEVAL_MISSING` for 15.00%, and `PARSER_LIMIT` for 10.00%.

V3.38 therefore confirms the boundary suspected after V3.37: most remaining
utility failures happen after identity has admitted a compatible claim and the
unchanged Evidence layer still refuses it. The next engineering phase should
study Evidence sufficiency. It should not expand or refine identity, retrieval,
or the parser on the basis of this dataset.

This phase made no algorithm change and did not enter Generation Evaluation.

## 3. Failure taxonomy

Attribution is applied only to an expected ANSWER that ended in ABSTAIN, using
the following frozen precedence:

1. `PARSER_LIMIT`: the annotated human-readable evidence structure was not
   recovered by the production parser.
2. `RETRIEVAL_MISSING`: no frozen relevant chunk reached the selected Evidence
   candidates.
3. `IDENTITY_ERROR`: relevant evidence arrived, but the identity boundary
   rejected an annotated compatible positive.
4. `EVIDENCE_TOO_STRICT`: relevant parsed evidence arrived and identity did
   not reject it, but the existing Evidence contract still abstained.
5. `UNSUPPORTED`: expected ABSTAIN controls and correct ANSWER outcomes; it is
   not counted in the false-refusal denominator.

The precedence prevents an identity outcome on malformed table text from
masking a known parser limitation, and prevents an Evidence label when the
supporting chunk never reached Evidence.

| `IDENTITY_ERROR` | 1 | 5.00% | below 30% |

Among the 20 false refusals, identity returned COMPATIBLE for 15, UNKNOWN for
three, and INCOMPATIBLE for two. Eighteen reached the existing Evidence layer;
only two stopped at the identity boundary. Fourteen had their reviewed,
parser-recoverable gold chunk in the selected Evidence candidates and were
still refused. This is the direct evidence for the sufficiency-boundary
diagnosis.

Module ownership, parameter inheritance, and configuration relationships show
that the problem is not limited to visually complex tables. Table cases add a
smaller, separately measured parser contribution.

## 5. Boundary decision

The pre-registered routing policy is strict `>30%` of false refusals:

| Condition | Observed | Route |
| --- | ---: | --- |
| `IDENTITY_ERROR > 30%` | 5.00% | no identity refinement |
| `RETRIEVAL_MISSING > 30%` | 15.00% | no retrieval improvement |
| `EVIDENCE_TOO_STRICT > 30%` | **70.00%** | **Evidence sufficiency refinement** |
| `PARSER_LIMIT > 30%` | 10.00% | no parser/table phase |

Recommended next phase: create a new DEV-only Evidence sufficiency candidate
that distinguishes explicit compatible ownership/inheritance evidence from
unsupported relations. The nine control false answers require a safety
constraint; a blanket reduction in abstention is not supported by this
analysis.

V3.38 itself stops at attribution. It does not authorize an algorithm change,
a sealed gate, Generation Evaluation, or Support rebuild.
