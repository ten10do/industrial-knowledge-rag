## 4. Attribution method

V3.46 separates two failure dimensions:

1. Claim representation: the needed attribute, qualifier, section, or reference ownership
   cannot be expressed by the frozen Evidence relation decision.
2. Claim selection/window: the relation vocabulary exists, but the owned countervalue does
   not survive as one bounded proposition available to the veto decision.

False-answer attribution uses manual record-level annotations frozen before the result is
generated. The public contract requires exact coverage of the 9 V3.45 false-answer IDs,
valid classes, responsibility/class agreement, a non-empty reason, and an explicit selected
signal observation.

False-refusal attribution is deterministic with this precedence:

1. `RETRIEVAL_MISSING` when the annotated gold chunk was not selected;
2. `IDENTITY_FALSE_REJECTION` when selected gold evidence was rejected by Identity;
3. `ROUTING_OUTSIDE_VERIFICATION` when compatible selected evidence did not enter the
   verification path.

An otherwise unclassified false refusal invalidates the reassessment rather than being placed
in a catch-all Evidence class.

The three vocabulary gaps are concrete rather than parser failures: the Evidence layer does
not represent `weigh`, PWR LED color, or readback-time guidance as bounded attributes. The
qualifier case treats an available `1 ms` option as supporting a query about the factory
setting, despite the owned factory value being `8 us`. The section case binds `65 g` while
ignoring the query's power-consumption section constraint. The reference case cannot
distinguish W521 co-occurrence from an owned weight-to-W521 reference.

## 6. Selected-signal analysis

Five of the nine false answers already have the decisive counter-signal somewhere in the
selected candidate set. They still remain ANSWER because the signal is not emitted as one
owned, bounded conflict:

- two input-current cases contain the correct `3.5 mA` countervalue but end on
  `ATTRIBUTE_RELATION_MISSING`;
- the factory-setting case contains the qualifier and competing setting but reports
  `DIRECT_SUPPORTED`;
- the section case contains the value but does not encode section ownership;
- the Page 61 hard negative retrieves the owned Page 60 reference but cannot bind the
  readback-time attribute.

The other four false answers lack a sufficient owned counter-signal in selected candidates.
V3.45 correctly preserves these instead of treating missing evidence as a veto. This confirms
that a future design must keep insufficiency separate from explicit contradiction.

## 10. Next phase recommendation

Enter **V3.47 Bounded Evidence Claim-Binding Design**.

The future candidate should be independent and additive over the frozen V3.45/V3.42 chain.
It should represent only the audited gaps:

- bounded Evidence attribute aliases for the three observed vocabulary gaps;
- explicit relation qualifiers, initially factory/default setting only;
- section ownership when the section is explicitly named in the query and evidence;
- reference ownership requiring a single attributable source-to-target relation;
- deterministic selection of the best explicit conflict instead of last-failure overwrite.

The candidate must preserve every V3.42/V3.45 ABSTAIN, require target + relation +
attribute/value/action, and veto only when the owned counter-signal is explicit. Missing
evidence, missing attributes, or cross-chunk co-occurrence must remain `PRESERVE`.

Do not modify retrieval, parser, Support, Identity, semantic judge, NLI threshold, or
open-sufficiency base logic. Do not enter independent generalization, a sealed gate, or
Generation Evaluation until the bounded candidate demonstrates safe veto utility on a new
DEV benchmark.
