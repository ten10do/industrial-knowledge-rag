## 4. Identity claim taxonomy

`IdentityClaim` = {product, family, model, module, scope, source, aliases, manufacturer}.

| IdentityEvidenceRelation | Binding rule |
|---|---|
| EXPLICIT | query names a document model alias (e.g. "ZD-100", "FP-X") |
| FAMILY_INHERITED | query names the document product family ("SJ series", "FP-X family") |
| SECTION_INHERITED | query anchors on "this section" / "the manual" context |
| DOCUMENT_INHERITED | generic product pronoun ("this drive", "the unit") bound to the document |
| UNSUPPORTED | safety constraint fired or no anchor |

Safety constraints (all enforced before any expansion):
1. **Different manufacturer → rejected** (deterministic manufacturer deny-list:
   `MANUFACTURER_MISMATCH_REJECTED`).
2. **Different product line → rejected** (hyphenated model tokens not owned by the document's
   aliases: `PRODUCT_LINE_MISMATCH_REJECTED`).
3. **Different parameter owner → rejected** (P####-style tokens must exist inside the target
   document: `PARAMETER_OWNER_MISMATCH_REJECTED`).
4. Multi-document ambiguity → refused (`MULTI_PRODUCT_CORPUS_UNRESOLVED`) — expansion only
   when every retrieved candidate belongs to ONE document.
5. Cross-reference assertions without a concrete, corpus-ownable target → refused
   (`REFERENCE_TARGET_UNVERIFIED`).

## 5. Implementation

- `backend/retrieval/identity_claim_v341.py` — `identity-v341-claim-expansion-candidate`
  (EXPERIMENTAL_CANDIDATE). Wraps the frozen `analyze_identity_aware_evidence`; intervenes
  ONLY when the decision is ABSTAIN and the identity boundary is INCOMPATIBLE
  (`NO_COMPATIBLE_IDENTITY_CLAIM`) or UNKNOWN (`IDENTITY_EVIDENCE_UNKNOWN` /
  `CLAIM_IDENTITY_UNKNOWN` / `QUERY_IDENTITY_UNKNOWN`) and the path did not delegate. On a
  verified claim it re-runs the frozen `analyze_mixed_evidence` path and tags the decision
  `V341_IDENTITY_CLAIM` with the claim relation + reason code.
- `backend/evaluation/v341_identity_claim.py` — public taxonomy, dataset validator, baseline
  classifier, metrics, per-case slices, acceptance policy.
- Untouched (SHA256-verified before/after): `identity_reasoning.py`, retrieval, parser, NLI
  judge, `semantic_judge_localnli.py`, `evidence_support.py` (support-v316.1), open
  sufficiency, `evidence_mixed.py`, `evidence_sufficiency_v340.py` (coverage relation).
- Frozen identity mechanics discovered (read-only): model-scoped queries against family-scoped
  claims yield `BROADER_EVIDENCE_SCOPE` → INCOMPATIBLE; digit-less queries yield
  `QUERY_IDENTITY_UNKNOWN` → UNKNOWN — both are exactly what document-local claims resolve.
