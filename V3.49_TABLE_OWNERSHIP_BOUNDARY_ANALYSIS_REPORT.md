## 2. Motivation

V3.48 found that 11/20 (55.00%) actionable false-answer or unsafe-veto cases involved
flattened table, row, section, or reference ownership. V3.49 tests the narrower question:
whether Evidence can safely determine that an observed value belongs to the requested
model and parameter rather than merely occurring nearby.

The candidate is deliberately conservative and one-directional. It composes the frozen
V3.47 runtime used by the V3.48 current state, never converts an existing abstention into
an answer, and may preserve an existing answer only when a structured ownership check
succeeds. This isolates the ownership boundary without changing retrieval or parser
behavior and without directly optimizing the known V3.48 cases.

## 3. Table ownership taxonomy

`TableOwnershipRelation` defines the registered boundary outputs:

| Relation | Required ownership proof |
|---|---|
| `DIRECT_ROW` | Attribute and value/action form one unambiguous row for the target model. |
| `COLUMN_BOUND` | Model/attribute/value roles are bound within one explicit column scope. |
| `HEADER_INHERITED` | A value inherits a unique, non-conflicting header in the same table region. |
| `SECTION_INHERITED` | A table row inherits a unique target and parameter scope from its section. |
| `CROSS_REFERENCE` | The reference target is explicit and locally owned by the requested attribute. |
| `UNSUPPORTED` | Any required scope is absent, conflicting, or ambiguous. |

Every decision also emits `confidence` and `reason_code`. The implementation requires the
structured claim components `target`, `relation`, `attribute`, and `value_or_action` before
ownership is considered. It checks same table region, header/parameter scope, target model
scope, and local conflicts. A failure returns `UNSUPPORTED`; adjacency alone is not intended
to be sufficient.

Merged-cell ownership is represented as inherited header/section scope rather than as a new
answer-generation mechanism. Cross-reference ownership requires an explicit local reference
marker. Manufacturer-level expansion, family inheritance, parameter borrowing, and
cross-model ownership are outside this contract.

## 7. Failure taxonomy

| Failure class | Count | Boundary implication |
|---|---:|---|
| Inherited baseline false refusal | 22 | Not created by the ownership candidate; includes 8 retrieval misses. |
| New conservative ownership veto | 5 | Valid answers rejected because flattened text cannot prove parameter or conflict-free scope. |
| Safe wrong-attribution veto | 6 | Ownership ambiguity correctly removes a baseline false answer. |
| Unsafe adjacency binding | 1 | Wrong column/row survives as a supported header inheritance. |

The unsafe case is decisive. The Siemens measurement-type table contains the rows
`Voltage 0000 0001` and `Thermocouple 0000 1010`. For the false claim that Voltage owns
`0000 1010`, the candidate sees the requested attribute and value within its three-line
window and emits `HEADER_INHERITED`, even though the value belongs to the next row. Thus
same table, same model, and short textual distance do not establish row or column ownership.

The five new false refusals occur in one multi-column, two default-value, and two
configuration queries. Three lack the registered evidence in the replayed candidates;
two retrieve it but the flattened representation produces conflicting or ambiguous
ownership. This confirms that a veto-only heuristic can lower FA while still moving error
mass into FR.

## 9. Responsibility decision

Decision: **Evidence needs a Table Ownership Boundary contract, but Evidence must not invent
that ownership from flattened line adjacency.**

Evidence owns the final verification rule: it may preserve or veto an evidence decision only
when target, relation, attribute/value/action, table region, model scope, parameter scope,
and absence of conflicting ownership are proven. It also owns `UNSUPPORTED` and the resulting
abstention when that proof is missing.

The structural provenance needed to satisfy that rule is a different responsibility. Row
IDs, column/header spans, merged-cell inheritance, table-region IDs, and cell-to-model roles
cannot be recovered safely from the current flattened chunks with proximity rules. That
provenance must be supplied through an explicit auditable structure contract; whether it is
owned by parser, chunker metadata, or another upstream representation layer remains outside
the frozen scope of V3.49.

Cross references and a small subset of direct rows are recoverable from existing text, but
3/30 ownership recall with one unsafe binding is insufficient to justify a runtime Evidence
capability. The experimental candidate must not be integrated.
