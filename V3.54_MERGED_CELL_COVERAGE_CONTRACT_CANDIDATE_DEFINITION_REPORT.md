## 3. Motivation and boundary

V3.53 established that direct `model_row_id == value_row_id` cannot express a value in a
descendant row of a vertically merged model cell. It selected
`ANCHOR_PLUS_COVERED_ROW_IDS` as the unique minimum safe representation.

V3.54 tests that representation without weakening V3.51. Coverage is usable only when the
frozen validator's sole failure is `MODEL_ROW_OWNERSHIP_MISMATCH`. Any independent model,
parameter, column, header, value, conflict, span, role, or lineage failure remains invalid.
Identity compatibility, adjacency, and span arithmetic never create coverage.

## 4. Candidate contract definition

The independent candidate is
`backend/retrieval/table_structure_proof_contract_v354_candidate.py`, version
`merged-cell-coverage-v354-candidate`, status `CONTRACT_CANDIDATE_ONLY`.

`MergedCellCoverage` supplies:

| Field | Contract role |
|---|---|
| `coverage_id` | Stable identity for one coverage assertion. |
| `document_id` / `table_region_id` | Exact physical table boundary. |
| `coverage_owner_scope_id` | Exact model owner; must match proof and claim. |
| `coverage_anchor_cell_id` | Stable physical merged-cell anchor. |
| `covered_row_ids` | Explicit, non-empty, unique row membership. |
| `chunk_ids` | Provenance link to the supplied proof. |
| `conflicting_coverage_ids` | Explicit overlap/conflict veto. |
| `coverage_kind` / `coverage_version` | Vertical-only typed contract identity. |

The validator returns `valid`, `reason_codes`, the frozen V3.51 `base_reason_codes`, and
`coverage_used`. Coverage recovery requires all of the following:

1. `COLUMN_BOUND` relation;
2. same document, table region, and model scope;
3. explicit membership of both anchor row and value row;
4. no duplicate membership and no conflicting coverage;
5. a valid vertical physical span and linked chunk provenance;
6. no frozen V3.51 error other than the one model-row mismatch.

`merged_cell_span` remains advisory physical metadata. The candidate checks that a vertical
merge is well formed, but never derives membership by counting or selecting adjacent rows.
Cross-chunk coverage replication is permitted only when all structural fields are stable;
membership drift is rejected by `validate_coverage_lineage`.

## 7. Failure taxonomy

All 36 invalid fixtures were rejected with their preregistered target reason. The main
classes were:

- explicit membership failures: outside value, missing anchor, duplicate or invalid row ID;
- scope failures: wrong document, table region, or owner model;
- conflict failures: existing owner conflict or conflicting coverage ID;
- structural failures: non-vertical/malformed span, wrong coverage kind, or column mismatch;
- provenance failures: detached/duplicate chunks, proof drift, or coverage-membership drift;
- frozen regression failures: header, row, qualifier, section, reference, and unsupported
  relation guards.

The raw reason ledger includes the inherited `MODEL_ROW_OWNERSHIP_MISMATCH` on rejected
coverage attempts. This is intentional: the candidate records the frozen base failure and
adds the decisive coverage veto instead of concealing the original condition.
