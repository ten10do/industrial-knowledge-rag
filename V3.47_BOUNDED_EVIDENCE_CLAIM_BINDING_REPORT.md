30 ANSWER and 30 ABSTAIN. Each registered claim-binding case has a 5/5 label split.

| Claim-binding case | Queries | ANSWER | ABSTAIN |
|---|---:|---:|---:|
| Attribute alias binding | 10 | 5 | 5 |

| Factory/default qualifier | 10 | 5 | 5 |

## 4. Implementation

`evidence-v347-bounded-claim-binding-candidate` composes the unchanged V3.45 decision and
adds `EvidenceClaimBindingRelation`:

- `OWNED_SUPPORTED`: the selected target-owned claim explicitly supports the requested
  attribute and value;
- `OWNED_CONFLICT`: the selected target-owned claim explicitly exposes a competing value,
  qualifier, section owner, or reference owner;
- `UNBOUND`: a safe no-op when a target, attribute, value, qualifier, section, or reference
  cannot be bound.

The candidate exposes `reason_code` and `confidence`, plus `VETO` or `PRESERVE`. It never
converts a V3.45 ABSTAIN into ANSWER and never treats missing evidence as contradiction.
Only an `OWNED_CONFLICT` at confidence at least 0.97 may veto an existing answer.

The deliberately bounded vocabulary covers only audited attribute aliases, PWR LED color,
factory/default qualifiers, explicitly named sections, explicit page references, and
deterministic support/conflict selection. If both support and conflict are observed, support
wins. No family inheritance, manufacturer expansion, parameter borrowing, or cross-model
leakage is authorized.

Retrieval, parser, Support, V3.41 Identity reasoning, semantic judge, NLI threshold,
open-sufficiency base logic, V3.42, and V3.45 were not modified.

## 7. Failure taxonomy

The 17 candidate false answers distribute as follows:

| Claim-binding case | False answers |
|---|---:|
| Factory/default qualifier | 4 |
| Attribute alias binding | 3 |
| LED row ownership | 3 |
| Section ownership | 3 |
| Best conflict selection | 3 |
| Reference ownership | 1 |

Fourteen false answers ended at `NO_EXPLICIT_OWNED_SIGNAL_PRESERVED`, two at
`EXPLICIT_ATTRIBUTE_VALUE_SUPPORTED`, and one at `ATTRIBUTE_UNBOUND_PRESERVED`. This is
consistent with the candidate's safety rule: it does not invent a conflict when production
table extraction splits an attribute, qualifier, and value across separate lines or when the
selected window lacks a single owned counterclaim.

The three new false refusals are unsafe binding errors:

- `V347-032`: a valid EL1417 100 g row was treated as outside the explicitly requested
  `Technical data` section because the section-distance heuristic used physical line distance
  inside a long extracted table;
- `V347-034`: the valid EL1417 3 mA input-current row was rejected for the same reason;
- `V347-054`: a selected Siemens 75 mA module-current row overrode the valid 3.7 mA digital-
  input current claim, demonstrating parameter borrowing within the same target document.

These are representation/ownership errors in the V3.47 candidate, not authorization to
change retrieval, parser, Identity, Support, or open sufficiency.

## 8. Safety analysis

| Safety/integrity observation | Required | Observed | Pass |
|---|---:|---:|---|
| Unsafe veto | 0 | 3 | No |
| Unsafe relax | 0 | 0 | Yes |
| Hard-negative FA increase | none | 17 -> 17 | Yes |
| Baseline replay mismatch | 0 | 0 | Yes |
| Candidate frozen | yes | yes | Yes |
| Protected hashes unchanged | yes | yes | Yes |
| One completed run per artifact | yes | yes | Yes |

The candidate never auto-answered on identity compatibility and never relaxed an abstention.
However, the three unsafe vetoes violate the central claim-binding safety boundary. Two use
line proximity as a proxy for table-section ownership; one borrows a value from a different
current attribute. Consequently, family and manufacturer expansion remain blocked, but
parameter borrowing is not adequately blocked by this design.

Engineering gates passed: targeted V3.47 tests reported `9 passed`; the complete backend
suite reported `746 passed, 2 skipped, 5 subtests passed`; and `npm.cmd run build` completed
successfully for the frontend. All 16 registered protected files still match the hashes frozen
before evaluation, and the private benchmark ignore check passed.

## 10. Next phase recommendation

Enter **V3.48 Bounded Evidence Claim-Binding Responsibility Reassessment** only after an
explicit next-stage instruction.

That reassessment should remain read-only over the V3.47 artifacts and determine separately:

- whether table cell/row ownership can be represented without parser or chunker changes;
- whether section ownership belongs in Evidence when production extraction flattens long
  parameter tables;
- whether same-unit values need an explicit attribute-role discriminator before any veto;
- which preserved false answers contain a complete owned counterclaim versus only
  co-occurring fragments.

Do not modify retrieval, parser, Support, Identity, semantic judge, NLI threshold, or open-
sufficiency base logic. Do not enter independent generalization, a sealed gate, Generation
Evaluation, or any later stage from this report.
