## 3. Motivation and method

V3.52 rejected all four valid vertically merged model-cell proofs with
`MODEL_ROW_OWNERSHIP_MISMATCH`. The model cell is anchored at the first physical row while
its values occupy four explicitly covered descendant rows. The current contract accepts
only direct row equality and has no way to express this coverage.

V3.53 does not weaken that equality check. It separates:

1. legitimate descendant membership that the schema cannot express;
2. a value row outside merged coverage;
3. a mismatched model owner;
4. an overlapping/conflicting owner;
5. malformed physical merge metadata.

Eight annotations were frozen before the reassessment ledger was generated. Annotation
correctness is derived from the frozen V3.52 expected/observed decisions, and responsibility
is derived from the registered coverage class.

## 5. Representation option analysis

| Option | Explicit membership | Preserves anchor | Stable lineage | Conflict representation | Decision |
|---|---|---|---|---|---|
| Span arithmetic | No | Yes | No | No | Unsafe |
| Duplicate model row ID into child rows | Superficially | No | No | No | Unsafe |
| Anchor plus explicit covered row IDs | Yes | Yes | Yes | Yes | **Minimum safe** |
| Full cell ownership graph | Yes | Yes | Yes | Yes | Safe but not minimal |

Span size cannot prove membership because stable row IDs are not ordered coordinates.
Inferring the next N rows would recreate proximity ownership. Duplicating the model's row ID
into every child row makes equality pass but falsifies the cell's physical anchor and makes
lineage auditing ambiguous.

A full ownership graph is expressive but adds unrelated graph semantics before they are
needed. Anchor plus explicit covered rows supplies every required safety property with the
smallest registered extension.

## 6. Minimum extension fields

The selected extension requires five fields:

| Field | Purpose |
|---|---|
| `coverage_id` | Stable identity for one merged-cell coverage assertion. |
| `coverage_owner_scope_id` | Model or other scope that owns the merged cell. |
| `coverage_anchor_cell_id` | Stable physical cell anchor; prevents duplicated-row identity. |
| `covered_row_ids` | Explicit row membership, including anchor and descendants. |
| `conflicting_coverage_ids` | Auditable overlapping or competing coverage assertions. |

Existing proof fields continue to supply document ID, table-region ID, model/parameter/value
scope, row and column IDs, source chunks, and physical `merged_cell_span`. The span remains
useful audit metadata but is not ownership proof by itself.

## 7. Required invariants

A future coverage validator must require:

1. non-empty, stable coverage identifiers;
2. `coverage_owner_scope_id == model_scope_id` for model-row coverage;
3. an anchor cell in the same document and table region as the proof;
4. explicit, non-empty, unique `covered_row_ids` including the anchor row;
5. `value_row_id` membership in `covered_row_ids`;
6. zero `conflicting_coverage_ids` and zero existing owner conflicts;
7. byte-stable coverage membership across chunk replication.

The direct `model_row_id == value_row_id` rule remains valid when no merged coverage is
provided. Coverage is an additional explicit proof route, not a relaxation of the direct-row
route. Model/parameter scope, column/header lineage, malformed span, and conflict guards all
remain unchanged.
